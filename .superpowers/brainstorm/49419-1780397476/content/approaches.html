Three approaches to the trim overlay

All three use ffmpeg for keyframe-accurate export via a file picker. The difference is the overlay UI.

A

Draggable handle timeline (Recommended)

A slim bar slides up from the bottom of the video with a full-width progress strip. Two draggable handles mark the in/out points. Click anywhere on the strip to jump to that position. Time codes shown next to each handle. "Save Trim" and "Cancel" buttons.

Pros

  • Intuitive, familiar UX
  • Visual feedback of selected range

Cons

  • Complex drag logic in overlay JS
  • IINA overlay mouse events can be finicky
B

Mark-in / Mark-out buttons

Overlay shows two buttons: "Set Start" and "Set End" — each captures the current playback position. Below them, a read-only display shows the selected range (e.g. 0:32 → 1:14 | duration: 0:42). "Save Trim" and "Cancel" buttons. Play the video, pause where you want, tap the button.

Pros

  • Simple, reliable implementation
  • Works great with keyboard shortcuts

Cons

  • No visual scrubbing in the trim UI itself
C

Time input fields

Overlay shows editable time fields for start and end. A "Use Current Time" button fills each field with the current playback position. A progress bar preview highlights the selected range but isn't draggable. Clean and precise.

Pros

  • Exact control with typed values
  • Moderate implementation complexity

Cons

  • More typing than visual trim tools
